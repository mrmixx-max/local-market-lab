# Local Market Lab v1.1 — Scope (Fokus: "Git für Portfolio-Research")

> Stand: v1.0.0-rc.1 (eingefroren). v1.1 baut evolutionär darauf auf.
> Keine neuen Major-Features außerhalb dieser 9 Punkte. Kein Scope-Creep.

## Positionierung (Leitplanke)

**Local Market Lab = Git für Portfolio-Research.**

- Versionierte Eingaben (Portfolio, Parameter, Datenquelle) → wie ein Commit
- Reproduzierbare Ergebnisse → jedes Resultat ist ein signiertes Run-Manifest
- Keine undurchsichtige Cloud → alles lokal, keine Uploads, kein Account
- Wettbewerbsvorteil vs. freie Python-Libs: **Bedienbarkeit** (UI + Manifeste
  + Reproduzierbarkeit out-of-the-box, nicht nur eine Funktion)
- Wettbewerbsvorteil vs. Cloud-Plattformen: **Datenschutz, Kontrolle,
  Nachvollziehbarkeit** ( lokales Recht, kein Vendor-Lock-in)

Jedes Feature in v1.1 muss diese Story stützen: Eingabe versionierbar? Ergebnis
nachvollziehbar? Kein Cloud-Zwang?

## v1.1 — Die 9 Punkte (Priorität Reihenfolge)

### P0 — Funktionslücken schließen (0 Code-Treffer heute)
1. **Steuer-Modul** (`packages/portfolio/tax.py`)
   - Realisationsprinzip, FIFO/Ø-Kurs-Anschaffung, Gewinn/Verlust-Buchung
   - Vorabpauschale (deutsche ETF-Besteuerung) als Option
   - Quellensteuer (withholding tax) bei Dividenden, anrechenbar/abzugsfähig
   - Keine Steuerberatung — reine Berechnung, disclaimer-pflichtig
   - Angebunden an Manifeste (Parameter-Hash enthält Steuer-Regime)

2. **HTML-Export** (`packages/reports/builders.py`)
   - Eigenständiges, inlinerbares HTML-Report (kein externes CSS/JS)
   - Gleiche Daten wie PDF/CSV, aber menschenlesbar im Browser
   - Disclaimer + Run-ID + Seed + Data-Hash im Footer (wie PDF/CSV)

### P1 — Vorhandenes härten ("sauber / verständlich / sehr gute Demo")
3. **CSV-Import sauber** (`packages/ingest/csv_import.py`)
   - Explizite Spalten-Mapping-Fehler ("Spalte 'price' fehlt in Zeile 4")
   - Encoding/Decimal-Separator-Erkennung (de EN/US), klare Meldung bei Scheitern
   - Validation: Datumssortierung, Negative-Werte, Duplicate-Check

4. **Yahoo-Finance-Import** (`packages/marketdata/yahoo_adapter.py`)
   - Robust gegen API-Limits (Rate-Limit-Message statt Crash)
   - Adjusted/unadjusted klar dokumentiert; FX-Policy bei fremder Währung
   - Offline-Fallback explizit ("kein Netz — nur lokale Quellen")

5. **Verständliche Fehlerberichte** (über alle Module)
   - Einheitliches `LmlError`-Format: Was ist passiert / Warum / Was tun
   - Keine Raw-Tracebacks im CLI/UI; Details in Log-Datei
   - Manifest-Integritätsfehler mit konkreter Zeile/Feld

6. **Onboarding-Demo** (`lml demo` + Web-UI Tour)
   - Echtes ETF/Aktien-Beispielportfolio (z.B. IWDA/EIMI/AGGH + 2 Aktien)
   - Führt durch: Import → Backtest → Risk (VaR/CVaR/DD) → Rebalancing →
     Manifest → Rerun → Export (HTML/PDF/CSV)
   - "Was siehst du" / "Warum reproduzierbar" als Inline-Hinweise

### P2 — Schon drin, aber auf v1.1-Niveau bringen
7. **ETF-/Aktienportfolios**: TER-Linie für ETFs, Dividenden-Wiederanlage-Option
8. **Gebühren/Steuern/Dividenden**: Gebühren-Modell bereits da; mit Steuer-Modul
   (P0-1) und Dividenden-Tx verknüpfen; Round-trip-Kosten explizit
9. **Rebalancing + Min-Vol**: P1.2 bereits solide; nur API-Feedback bei
   `below_minimum` verständlicher machen (siehe P1-5)

## Nicht in v1.1 (explizit ausgeklammert)
- Keine Cloud-Sync, keine Accounts, kein Telemetrie
- Keine Broker-/Order-API (wie bisher)
- Keine ML-Modell-Trainings-Pipeline (nur Metriken/Reports)
- Keine Portfolio-Ziele/Risiko-Budgets (P2-Rest, auf v1.2 verschoben)
- Kein Worker-Restart-HA-Fix für Job-Queue (bekannte Medium-Einschränkung)
